# U.S. Web Design System

## When to use

Use when a U.S. public-service project needs a coherent reference, or when studying accessible service patterns with explicit content and institutional context. Ask which service standards apply and whether adopting the system is a requirement or a comparison option.

## What to inspect

Navigate among principles, patterns, components and the maturity model instead of starting with a template screenshot. Check the current package and documentation version. The user-profile family illustrates how institutional policy can change field guidance; it should not be treated as a timeless inventory of data every product must collect.

## What to borrow and adapt

Borrow the connection between a user job, content, implementation guidance and incremental adoption. For a local benefits service, map language access, form completion and recovery before selecting components. The language-pattern family is especially useful for distinguishing a fully translated site from a site with only selected translated materials.

## Mismatches and limits

USWDS carries federal context and policy obligations. Adapt jurisdiction, language, identity and information requirements rather than copying official banners or collecting unnecessary profile data. Homepage and pattern-source inspection did not test a deployed service, a responsive template or assistive technology. The observed v3.14.0 label is a snapshot; verify the installed version and current standards before implementation.
