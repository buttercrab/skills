# Figma UI3: visible state in repeated expert work

## When to use

Use when an expert repeatedly checks a property while manipulating an object: drawing tools, video editors, admin consoles, or a dense configuration panel. The match is state inspection and correction cost, not a recommendation to imitate Figma's entire layout.

## What to inspect

Read the docked-panel and blend-mode sections, then the clip-content reversal. The account explains why an icon or nested option could make the panel quieter while adding repeated inspection or action cost. It does not disclose a controlled effect estimate.

## What to borrow and adapt

Classify what users need to see separately from what they occasionally need to invoke. For an operations table, a visible nondefault allocation value might matter more than keeping every row visually identical. Compare an always-visible value with a compact default-state control; retain a clear route for changing or removing the exception.

Adapt the decision to task frequency, screen size and adjacent work. A static screenshot cannot tell how often the hidden state is checked. Ask about the actual repeated occasion before deciding whether to hide it.

## Mismatches and limits

This is a historical product-team account, not a live test of current Figma or proof against icons and progressive disclosure. An occasional novice task may benefit from more guidance and fewer simultaneous controls. The inspected images show historical explorations; they do not establish current product behavior or an aesthetic fit for another task. Linear's triage case offers a different example where explicit decisions, rather than continuous property inspection, dominate.
