# UI/UX Pro Max: contextual local design search

## When to use

Select this when the task needs a catalog-style source of design options or stack-specific implementation guidance. It is especially relevant to the library’s discovery problem because it distinguishes product-wide direction, targeted concerns and known-stack searches.

## What to inspect

Read the Query Contract before the example commands. Inspect the source’s returned domain/identity checks, contextual retry and no-verified-match behavior. Review persistence and existing master/override rules separately from searching; they are different operations with different effects.

## What to borrow and adapt

Borrow searching by one dominant intent and a useful constraint, detecting the actual stack, and checking returned applicability before using it. For a form correction, search the semantic outcome first, then obtain implementation detail for the project’s stack. Preserve already accepted design decisions when saving or updating a system.

## Mismatches and limits

The data totals and style names describe the package, not measured recommendation quality. Generalized numeric UX rules still need the applicable standard and context. The inspected instruction describes a Python search script; its retrieval, data quality and persistence were not executed or audited here. Running it or forcing overwrites requires separate task authority. Do not turn a nearest catalog result into a universal design rule.
