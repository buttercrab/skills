# GOV.UK Design System

## When to use

Start here when a person must complete an occasional, consequential service transaction and needs understandable questions, progress and correction. It is especially relevant when the agent needs a coherent family of patterns rather than a single fashionable component.

## What to inspect

Use the system's styles/components/patterns distinction to locate the right level of guidance. Read the pattern for the actual user job, then its component and accessibility notes. The homepage is a route into maintainer guidance, not sufficient implementation instruction by itself.

## What to borrow and adapt

Borrow the connection between content, semantic components and an end-to-end task. For a local membership application, for example, use a concise question protocol and a review/correction route while adapting vocabulary, eligibility and support to the community. Preserve the chosen project's own identity; a GOV.UK-looking page would imply an authority that an unrelated product may not possess.

## Mismatches and limits

This is a government-service system with its own brand, conventions and institutional requirements. It does not decide the best information density for expert operators, an expressive publication's atmosphere, or a game's interaction model. Homepage announcements establish documentation state, not a passing accessibility audit of any downstream implementation. No screen was visually inspected for this card.
