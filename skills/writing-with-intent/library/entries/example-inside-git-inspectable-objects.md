## When to use

When a reader can recognize an interface but cannot explain what its parts represent. Ask what they already know before choosing an inventory.

## What to inspect

The opening promise, recurring file examples and closing admission that internals alone do not explain every operation.

## Craft trace

Reader question: what is actually in this hidden directory? Concrete entries become the organizing unit; similar representations are compared locally. The closing boundary prevents a parts tour from promising complete operational mastery.

## Revision implications

Our proposed transfer: replace an abstract overview paragraph with one inspectable object, its representation and the question it answers. Keep comparable entries parallel; add a separate route for workflows the inventory cannot explain.

## What to borrow and adapt

Use a stable comparison unit and reveal exceptions beside the relevant part. Choose examples from the user’s actual system instead of borrowing Git terminology.

## Mismatches and limits

A directory tour mismatches readers trying to complete a specific task immediately. This craft reading does not certify every technical simplification or establish current Git behavior.
