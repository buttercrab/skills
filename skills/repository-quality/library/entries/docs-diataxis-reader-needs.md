# Diataxis: organize around the reader need before moving folders

## When to use

Use when a README mixes onboarding, recipes and exhaustive reference, or a proposed documentation restructure lacks a specific reader problem.

## What to inspect

Read the process guidance alongside the compass. The framework separates learning or doing from acquiring or applying understanding, but explicitly warns against starting with empty top-level sections. Its advice is iterative rather than a template-completion exercise.

## What to borrow and adapt

Choose a real reader occasion: first successful invocation, an experienced user's repair task, exact option lookup, or understanding a tradeoff. Improve one relevant page and link it from the entry point. Split content when mixed purposes make that reader's task harder. For a small CLI, a short quickstart and an accurate option reference may be sufficient; absence of four directories is not itself a defect.

## Mismatches and limits

This is an author framework, not controlled evidence of a universal navigation scheme. It does not determine package boundaries, enforce API compatibility or authorize publishing. A product can need multiple audiences or mixed-mode entry pages; assess the actual task before renaming all documentation.
