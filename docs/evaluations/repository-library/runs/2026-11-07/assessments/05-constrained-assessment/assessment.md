## Prioritized corrections

1. **P1 — Restore the documented parse-error contract.** `repository/src/signal_window/cli.py` lets `ValueError` escape from `parse_lines`; the README promises line-numbered errors, exit 2 and no traceback. `repository/src/signal_window/parser.py` splits without checking for `=`, so a missing separator raises an uncontextualized unpacking `ValueError`. Small correction: validate separator presence in the parser, raise a line-numbered `ValueError`, and translate parser `ValueError` at the CLI boundary to a concise stderr diagnostic and status 2. Keep the library exception type and CLI callable signature. Preserve parsing all rows before writing stdout so bad input cannot leave a plausible partial TSV. Test through public import and CLI invocation, not only an internal helper.
2. **P1 — Protect TSV row boundaries at their source.** The parser rejects empty labels but accepts internal tabs/newlines in a label, which `cli.py` prints verbatim. Source-derived examples `a\tb=2` and a library iterable item containing an embedded newline before `=2` produce ambiguous TSV rows. These examples were not executed. `maintainer-note.md` explicitly authorizes rejecting these label characters with `ValueError`; do so with the physical input line number. Preserve normal file line endings, valid signed integers and existing blank-line handling. Avoid changing whitespace normalization or inventing a stricter integer syntax during this patch.
3. **P1 release evidence — Exercise the packaged public boundary.** `repository/pyproject.toml` coherently declares setuptools, discovery under `src`, Python >=3.11, version 0.6.2 and `signal-window = signal_window.cli:main`. No packaging defect is demonstrated. The configured workflow at `repository/.github/workflows/check.yml` runs only Python 3.11 source tests with `PYTHONPATH=src`; it never installs the project or invokes its script. Add a compact built-wheel smoke check alongside fast tests, with no source-path override and a working directory outside the checkout. Check imports, console entry point, metadata and output/error behavior. This closes a real evidence gap without changing build backend or copying a large platform matrix.
