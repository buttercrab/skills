# First-edition repository assessment development protocol

Date: 2026-11-07. Scope: five source-only fictional repository assessments using the frozen `repository-quality-v1` package. No baseline or causal-effect comparison is claimed.

An independent fixture author created prompts, raw repository snapshots, evaluator notes and checksums without reading the new package/cards/research. The workflow author wrote the instructions before reading case contents, froze the 61-file package, then read the cases to coordinate scripted replies. This separation is procedural, not filesystem access control. Original prompts/keys/checksums remain unchanged.

Each runner gets a fresh non-forked context, the same frozen guide, its prompt and raw repository snapshot, and common read/write restrictions. The inherited model/reasoning configuration is used without overrides. Mandatory host instructions remain applicable; record any additional guide use. The guide is read-only; runners may use only its local catalog read/search commands. No network/source fetches, upstream code, fixture scripts, tests/builds, dependency installs, source edits, git operations, external writes or production actions are permitted. Deliver an assessment/plan, not an implementation. Case 05's user request explicitly permits two bounded read-only subagents; they inherit the same source/effect limits and use separate output files. Other cases do not request delegation.

A runner may ask a consequential human-owned question. Deliver only the applicable scripted fact from that case's evaluator notes, log the exact reply and preserve its effect. If no answer exists, tell the runner the information is unavailable and to complete the independent assessment with that uncertainty. Do not supply private fit criteria, a preferred resource or a gold folder tree. The runner may finish without questions where the brief is sufficient. No question-count, source-count or output-length target applies.

Output: `assessment.md`, `receipts.json`, `work-log.md` in the assigned run directory. Receipts distinguish inspected fixture paths from local card annotations. Reading a card does not repeat its underlying primary-source or curator observations. The configuration can support intended mechanics, not a passing check, installed artifact, protected branch or publication. Preserve uninspected/unknown outcomes.

Freeze final artifacts before independent review. The reviewer receives raw request/snapshot, actual relayed facts, outputs and evaluator notes; it did not author the workflow or assessments. Assess concrete change-path coverage, contextual reference transfer, proportional actions, evidence discipline and scope, allowing justified alternatives. Account for facts never delivered and for questions left unresolved. Report defects and omissions directly; no aggregate effectiveness or reliability claim. Source/code inspection does not demonstrate runtime behavior, usability or release success.

The native tool trace is not fully archived. Runner logs/receipts, coordinator relays, fixture/guide hashes and output files support a bounded review, not independent proof of every tool action. A reported policy/scope breach excludes the affected output from acceptance conclusions; preserve it diagnostically. No retrospective cost/timing claims. Cases become development material after exposure; future comparative claims require fresh tasks and appropriate controls.

Research source inspection, structural/tool tests, assessment artifacts and actual runtime testing are separate evidence. Full upstream source bodies were not frozen or redistributed; the package contains original annotations and exact locators. No real project is an implementation target in this evaluation.
