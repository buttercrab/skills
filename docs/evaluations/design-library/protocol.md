# Design-library source, selection and application evaluation

Status: fixture proposal, 2026-11-07. **No trials have run.** The cases were authored without reading the target package, new catalog, current research or old case prompts. The author read only the approved library plan and old pilot results. These are new situations, but the public case-family requirements and prior failures were known. They are not evidence of effectiveness.

## Scope and deliverable

Evaluate finding, understanding, selecting and applying resources before making UI-quality claims. Every runner returns a compact reference/match packet and a concretely applied screen, flow or content outline addressing the request. No app build, local preview, rendered artifact, installation or browser trial is requested. Case 07 keeps alternatives open; case 06 needs a narrow repair rather than a reference tour. Length, card count and question count are not success metrics.

Expected output contains:

1. Settled context, material assumptions and unresolved constraints, proportionate to the request.
2. Candidate roles/sources, fit and decisive mismatch; useful alternatives and the user's resulting choices. Distinguish chosen, supporting, rejected and unresolved leads.
3. Concrete proposed states/screens/content with links from selected resource portions to actual decisions. Sources must change or justify a specific part of the outline, not merely decorate a bibliography.
4. Access/evidence limits and a short receipt record. Report unavailable/no-good-match honestly.

Use ordinary source-reading and search facilities only as authorized. Receipt records are observable actions and decisions, never hidden reasoning or private chain-of-thought.

## Isolation and freeze sequence

1. Freeze these case prompts, coordinator keys, protocol and rubric before the case author sees any card. Record file hashes and author exposure history. Do not let catalog curators optimize against these prompts or private criteria before freeze. Repository location is organizational separation, not access control: runner dispatch must explicitly withhold private files.
2. Freeze the corpus: cards, generated views, source bodies/snapshots, access outcomes, tool inventory and versions. Preserve the old pilot entrypoint as the baseline instruction snapshot. Baseline means the actual prior pilot, not a deliberately weaker prompt or removal of ordinary host capabilities.
3. An independent mapper, who did not curate or author the workflow, reads frozen cards and private role-level criteria. Before any run, map admissible roles to actual card IDs, supporting portions and context mismatches. Add reasonable alternatives, not one gold brand. Record roles with no credible catalog match and sources requiring further inspection. Do not show the mapped key to runners, workflow authors or the original case author. If no independent mapper is available, label relevance judgments exploratory and do not call recall pre-registered.
4. Independently freeze a shared external-search packet if discovery beyond the catalog is evaluated: same query/result/source material and recorded unavailable states in both arms. User-provided policy facts remain distinct from published source evidence. If live search must replace a frozen packet, freeze the route, authorization, window and reconciliation rule in advance; record drift and do not silently give one arm sources unavailable to the other.
5. Freeze dispatch prompts, condition mapping, coordinator scripts, limits, randomization seed and planned reviewer assignment. Save hashes; trials may then begin under a separately authorized execution request. This document does not authorize trials.

Any case read by a workflow author/runner before its intended run becomes development material for that person. Preserve it and create a fresh replacement for a later held-out claim; do not relabel it untouched. None of the old six pilot cases is held out for this cohort. Curators should receive coverage families, not this private test set. Freeze corrections before runs; changes after exposure require versioning and a new cohort or a stated development-only limitation.

## Paired conditions and environment

Primary comparison: old pilot guidance versus expanded workflow, **same new catalog**, same source bodies/versions, same frozen search material, same host instructions/other skills, same model/reasoning configuration, same tools and limits. Both may read the catalog, research authorized sources, ask questions and apply resources. Do not remove normal baseline research or clarification ability. The difference is the target workflow guidance. A later installed-full-package comparison is a separate estimand and must not be pooled with this one.

Fresh isolated contexts and output directories per case/arm; no sibling outputs, condition keys, private rubric files or running agent memory. Record which extra skills were used and their versions. Keep tools available equivalently; record actual tool access and errors. Predeclare a common generous action/time ceiling if needed, measured consistently; no retrospective time/cost claim when those data are absent. Randomize arm order per case and review neutral output labels. Scheduling and model nondeterminism remain limitations; repeated seeds/runs are needed for reliability claims.

The core source-only cohort can complete with filesystem source cards and supplied source bodies. Public HTTPS read-only primary evidence is optional **only when separately authorized in that run's environment** and equally available to both arms. Zero local browser pages: no `file:`, localhost, loopback, custom preview protocols, servers, headless rendering, alternate browser surfaces or app builds. No installs, asset copying, publishing or mutation of source services. Reading a linked skill is not activating its instructions or granting its tool/installation demands.

On policy denial, stop that blocked outcome immediately. Do not retry it via another protocol, surface, headless tool or equivalent route. Record the requested outcome, denial and stopped work. Continue only genuinely independent authorized work, with blocked evidence labeled unavailable. A route accepted by another tool does not waive an earlier outcome restriction. An outcome-level denial or scope breach cannot be converted into a pass by source/mock checks. A breach invalidates the affected paired acceptance comparison; preserve observations and exclude them rather than silently replacing them. An optional visual outcome blocked in both arms does not invalidate independently authorized source judgments; mark the visual dimension unassessed.

## Scripted user interaction

The coordinator sees private keys; runners receive only `prompt.md` and normal common instructions. Match questions by meaning, not wording. Deliver the applicable fact block when a consequential question reaches that topic. Do not volunteer private fit criteria or steer toward catalog brands. If a question combines topics, return the relevant blocks together. If asked something unspecified, say: “That is not settled; make and label a reasonable assumption if it doesn't block the outline.” Do not invent hidden preferences.

Send each case's “after shortlist” or other triggered direction once at the first substantive matching point, even if the runner asks no questions. If the runner finishes without a shortlist, send it as one revision request. For case 06, no shortlist is required and no catalog-pushing feedback is sent. Log trigger, exact delivered text and runner revision. If the trigger cannot occur within the predeclared limit, record unmet trigger rather than adding unequal extra work. Questions can be few or absent when the brief/delegation warrants it. Scripted reactions test instruction fidelity, not human satisfaction or whether real people find the questions useful.

## Receipts and evidence levels

For each material candidate/decision, collect ID/source locator, exact section/screen/state or version, access mode/outcome, date, fit/mismatch, borrow/adapt decision and resulting outline locator. Capture relevant query families/catalog regions and candidate disposition; do not require reading every card or exposing private reasoning. Preserve complete native tool traces when available, coordinator messages and final artifacts; label summaries as summaries.

Maintain separate evidence columns (none is a substitute for another):

| Evidence | What can be claimed |
| --- | --- |
| Source-card inspection | Card annotations and their stated limits were read; no automatic credit for underlying source verification. |
| Underlying primary material inspection | The specified original section/version supports the attributed claim. A secondary account remains secondary. |
| Visual sample viewed | Actual identified image/screen was viewed on an authorized surface; supports visible qualities at that sample's scope only. A URL, alt text or descriptive tags do not qualify. |
| Flow documented | Inspected sequence/state model or detailed account supports stated flow; distinguish current, historical and hypothetical behavior. |
| Interaction tested | Recorded direct execution of the interaction in an authorized environment. This cohort requests no such tests; score not assessed. |

A previously curated card may report its own historical visual inspection; the runner must attribute that report rather than say “I viewed it.” If image inspection is unavailable, source-based matching and application remain assessable; visual fit is unassessed. Do not silently penalize truthful limits as though they were failures to render an app.

## Order, decoys and gap tests

After the mapper freezes admissibility, create matched index permutations using a recorded seed, preserving content, source availability and identifiers. In one adversarial permutation, put a highly relevant resource late and an attractive context-mismatched resource early. Add decoys only as frozen common corpus material with truthful annotations; do not falsify card evidence. Keep token/context accessibility equivalent: a late resource must remain discoverable by normal search, not fall outside the provided corpus. Predetermine which cases/replicates receive permutations; don't choose after seeing results.

Compare relevant role coverage and selected-fit changes under ordering, not a requirement to read the entire corpus or to reject every attractive visual resource. Case 08 permits no complete match; case 05 includes a fictional lead whose global nonexistence cannot be proved by an unsuccessful search. Report a gap or an inspected limited transfer rather than reward forced recommendation. Missing a genuinely applicable late resource is a retrieval observation, not proof of universal recall failure.

## Review and reporting

Use rubric.md dimension by dimension. A condition-blind reviewer receives requests, delivered scripted facts, neutral artifacts and evidence receipts plus the mapper's key, without condition labels or workflow text. Freeze judgments before unblinding. A second reviewer adjudicates consequential relevance disputes and adds defensible alternatives rather than rejecting them because they were absent from an initial key. Report those additions transparently; they must not rescue one condition selectively.

Publish per-case dimensions, blocked/unassessed outcomes, omissions, mismatches and application examples. Report applicable-role recall only against the declared frozen corpus/key, not the internet; report precision of consequential selected roles and harmful mismatches separately. Do not average away a scope/evidence-integrity failure. No overall winner is required. Source-only outlines do not demonstrate rendered beauty, accessibility conformance, interaction success, native performance or real-person creativity. Small ties/favorable runs establish neither equivalence nor general reliability. Preserve all prior pilot failures/exclusions unchanged.
