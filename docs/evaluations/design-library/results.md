# Design library: delivery and matching evaluation

Date: 2026-11-07. The first catalog-backed design edition delivers **107 annotated resources**: 16 skills, 11 tools, 34 product/flow/visual examples, 24 systems/patterns and 22 foundations. There are 106 curated entries and one partially inspected candidate. Start with the [library](../../../skills/design-with-intent/library/index.md), [operating skill](../../../skills/design-with-intent/SKILL.md) or [curation record](../../research/design-library/index.md).

The skill discovers relevant and neighboring resources, asks about consequential missing human direction, compares fit and mismatches, and carries selected mechanisms into the requested artifact. Detailed briefs, explicit creative delegation, exploration without a final choice and narrow repairs have separate proportional paths. Reading a third-party skill does not install or activate it.

Later revision: the [master-skill development iteration](master-skill-iteration.md) changes operating guidance after the frozen trials. Results below concern the archived catalog-v1 instructions; they do not evaluate that later wording.

## What was tested

Eight new cases produced sixteen independent reference packets and applied screen/flow/content outlines. Cases were authored separately from catalog curation; an independent mapper froze admissible resource roles before execution. Each pair received the **same new library and search helper**. The baseline entrypoint/references came from the actual prior pilot v1.1; the other condition received the expanded discovery/selection workflow. Both could research and ask questions.

Fresh non-forked agent contexts used the inherited model/effort and normal host capabilities, with no model override. Condition allocation and neutral review labels were randomized with recorded seeds. Two independent reviewers split the cases, read neutral outputs and actual delivered conversation facts, and froze their judgments before labels were revealed. Neither reviewer was the catalog curator, workflow author, fixture author or trial runner. This is one run per case/condition, not a reliability estimate or a replicated inter-rater study.

Public HTTPS primary-source reading and source screenshots were permitted equally. Complete live source/search responses were not frozen. Reported access failures and additional discoveries varied, so the comparison cannot cleanly isolate instruction effects. The proposed adversarial order permutations/decoy experiment was not executed. No timing or token-cost conclusion is supported.

The [protocol](protocol.md), [rubric](rubric.md), independent mapping, source receipts, delivered relays and [frozen run archive](runs/2026-11-07/README.md) preserve the assessment boundaries. The protocol/rubric retain their pre-run proposal status; this report records actual execution and departures.

Other document-level dimensions receive 3/3 in both arms in these reviewers’ records. That ceiling and the small sample limit discrimination; equal ratings do not demonstrate equivalence. More references and higher discovery ratings do not by themselves establish a better final experience. There is **no demonstrated overall advantage or general reliability claim** for the expanded instruction text. Both arms had the new resource asset, so this experiment does not estimate the benefit of having the library versus having none.

Role coverage uses a frozen finite mapping, not internet recall. Reviews separately record considered resources, materially selected portions and application supported directly by supplied facts. Valid new external sources are documented as posthoc alternatives without modifying the frozen denominator. Different-source solutions can both be appropriate.

### Scope reconciliation and delivery limitations

Case 05’s expanded-workflow runner reports briefly writing `/private/tmp/05-birch-receipts-validated.json`, then removing it. The actual common instructions require **all writes within the assigned trial directory**. This is a scope breach even though the scratch file was within the host’s writable temporary area and no policy workaround/source-service mutation is reported. Under the frozen protocol, **case 05 is excluded from paired acceptance conclusions**. Both final packets and blind diagnostic judgments are preserved. Seven pairs remain eligible for bounded source/outline comparison, with the other limitations below; this is not a seven-pair validated UI result.

The coordinator relayed optional facts only when elicited. Case 02 consequently has unequal policy exposure. Optional private facts in cases 03/04/06/07 were never delivered to either runner; reviewers did not treat them as disobeyed instructions. Missing frozen roles remain visible, without inventing user requirements. Initial assistant packets are summarized in the coordinator record, so precise before/after comparisons are limited.

## Evidence and validation limits

Card inspection, underlying primary-source reading, visual samples, documented flows and tested interactions are separate evidence. The collection has 23 cards with curator visual receipts, 27 with documented-flow receipts and two narrowly tested public interactions. Those historical curator observations are not automatically runner observations. Trial receipts are runner reports plus coordinator summaries, not complete native tool transcripts.

No app was built or evaluated in this cohort. No rendered beauty, current native behavior, accessibility conformance, gloved usability or real-person creative satisfaction is established. Scripted keep/reject/mix feedback tests whether a revision follows supplied direction. It does not measure whether a person likes the questions or result. No policy workaround was reported in the new cohort; case 05 has the separate write-location scope breach described above. The available records are not an independent replay of every native tool action.

The earlier [execution pilot](../design-pilot/results.md), including its browser-policy violations and invalidated comparisons, remains unchanged and separate. This source/outline cohort does not rehabilitate those results.

The catalog validator, skill metadata validator and portable package-copy check passed. The relevant test suites passed **44 checks**: 18 catalog tests, four package tests and 22 installer tests. All 119 frozen package files matched the final package, and the identical catalog/helper bytes were checked across all sixteen trial guides. Structural tests establish package consistency, not the truth of every source claim.

## Maintenance

Trial-discovered leads are recorded in the [discovery queue](../../research/design-library/index.md#discovery-and-maintenance-queue), separately from curated recommendations. New resources need source inspection and contextual annotations before promotion. Preserve stable IDs, update access/version evidence, rebuild indexes and validate after changes. The frozen catalog was not modified to fit these evaluation cases. No global installation, publishing or recurring automation was performed.
