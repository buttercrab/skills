## Administration

1. Give the assessed assistant only a case's prompt.md and snapshot/ files. Keep evaluator-notes.md and this administration section out of its input.
2. Preserve paths so answers can cite source lines. Do not give an architecture reference, product preference, or preferred folder layout.
3. evaluator-notes.md contains private claim-specific evidence keys, acceptable alternatives, and when applicable a scripted response to a genuine missing policy question. Reveal an answer only if that question is asked. Use the documented no-answer fallback when no answer is available.
4. Assess source evidence, constraint handling, uncertainty labels, and the purpose/failure paths of diagram source. Do not score by diagram count, stack brand, or resemblance to a reference implementation.
5. Each case's SHA256SUMS pins prompt, snapshots, and evaluator notes. Verify from its directory using a checksum reader; do not execute fixture application code or tests. The checksum file does not hash itself.

These cases authorize neither application edits nor live service access. Diagrams and proposals can describe proposed changes while explicitly distinguishing them from observed current state.
