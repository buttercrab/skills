# Private evaluator evidence key

This case should reveal whether the assistant reasons from a hard constraint instead of forcing synchronous RPC, reverse callbacks, network polling, or a two-way broker. Daily paper acknowledgment is explicitly approved; do not ask whether it is allowed. Transfer and archive completion are distinct. Local idempotency and atomic archive/receipt state, stable transfer/object/version IDs, manifest/digest verification, reassembly/completeness if needed, and safe dedup/replay handling are reasonable choices, not a mandatory recipe.

Retention starts after explicit valid archive acknowledgment, then runs 45 days. Seven-day prototype deletion violates policy. Delayed/out-of-order transfers and clock skew preclude relying solely on timestamp order. A file digest detects corruption relative to an established manifest but does not establish sender authenticity. Key enrollment/trust root is a true unresolved evidence gap, not a missing technology preference. A good bounded proposal can specify an authentication interface and gate authenticity claims/acceptance on approved enrollment; it must not claim secure signing is already available.

Paper acknowledgment needs transfer/digest binding, archive commit/verification meaning, duplicate-safe and typo-resistant entry, audit, and a way to reconcile mismatch. Exact paper encoding is a design choice. Suggested no-answer fallback: retain source, mark transfer unconfirmed, provide manual reconciliation and retry, and explicitly hold any authenticity acceptance pending trust evidence. Do not invent an approved key ceremony or bypass the one-way restriction.

No scripted human answer: the genuine unknown requires evidence or approval from security, not a guessed answer. User may still receive a useful proposal with that boundary. Diagrams should show domains, one-way transport, human paper path, local durable states, and loss/corruption/replay or acknowledgment error. No external reference match is required, and a citation to a famous distributed-systems pattern is not a substitute for reasoning from the supplied facts.
