## Mechanism-level findings and transfer limits

1. **SQLite:** rollback-journal finalization, a WAL commit marker and checkpoint are different boundaries. The pager ERROR contract describes why inconsistent cached state cannot simply become a normal reader. Live rollback documentation retains historical VFS discussion; selected current mirror comments are not a device-level durability experiment.
2. **PostgreSQL:** the supervisor rationale deliberately avoids ordinary shared-lock participation, while BackendMain initializes a session backend and hands off to PostgresMain. The tutorial resolves to documentation version18, while inspected source HEAD is a separate development snapshot. A process-per-connection explanation is not a current benchmark or universal design recommendation.
3. **rust-analyzer:** architecture prose identifies intended absences and API boundaries; syntax represents invalid text as a tree plus errors; AnalysisHost creates snapshots and documents cancellation after changes. Some prose code-map names are historical. No linked picture or latency/invalidation experiment was inspected visually or executed.
4. **Valkey:** AOF BASE/INCR/HISTORY and manifest state separate compaction authority from data synchronization policy. The configuration's rewrite-related fsync setting qualifies broad durability shorthand. Do not convert “every second” into a universal upper bound on real loss under arbitrary failures.
5. **Kubernetes:** manageReplicas records expected observations before requests, adjusts skipped/failed operations, and the expectations cache can permit sync after fulfillment, expiry or missing/error state. Expiration is not completion. A controller issuing API operations is not directly running the workload it describes.
6. **etcd Raft:** host storage/network/application obligations are outside the deterministic core. README ordinary ordering and the Ready field's AsyncStorageWrites exceptions must be read together; no unconditional parallel-I/O claim follows from a simplified loop. Committed log work and external effects remain distinct.
7. **NATS JetStream:** consumer pending deadlines/backoff/redelivery state has no knowledge of an arbitrary external effect. The pinned policy enum and processNak/checkPending branches supply a source-level control model, not proof of observed delivery. A retention outcome, terminal consumer handling and business completion are separate.
8. **DuckDB:** semantic query transformations differ from runtime pipeline-event dependencies and local source/sink/operator state. The docs resolve to2.0 and the pinned source contains development detail; neither is a captured query plan, scheduling run or performance result.
9. **Temporal Go SDK:** workflow replay restrictions and activity behavior create a meaningful boundary despite procedural syntax. Cancellation observation depends on server capability/heartbeat path; local activities are a distinct alternative. No claim of exactly-once business effects, replay safety of arbitrary upgrades or managed-service deployment follows.
10. **Bazel Skyframe:** Environment dependency requests and missing-value restarts support the documented incremental model. SkyValue's tiny interface does not enforce all documented immutability/hermeticity properties by itself. A dependency edge is not a network call, and a cache icon does not demonstrate tracked inputs.

## Discovery, access and evidence boundaries

- Repository revision discovery used approved GitHub read API `/repos/<owner>/<repo>/commits/HEAD`, then source fetches with that SHA. Exact selected revisions are preserved per card, so later mutable HEADs do not silently change the annotated case.
- Direct primary documentation reads followed the system question, not an internet popularity list: commit/recovery, supervisor/session, persistence, control loop, acknowledgment, query stages and dependency evaluation. Documented architecture, selected code and deployment observation remain different evidence.
- Initial DuckDB `src/execution/executor.cpp` returned404; the owning inspected path is `src/parallel/executor.cpp`. Initial Bazel `src/main/java/com/google/devtools/build/skyframe/SkyframeExecutor.java` omitted `lib` and returned404. The corrected executor's import-heavy opening was discovery only, not cited as substantive architecture proof; the final card uses the actual core SkyFunction/SkyValue interfaces instead.
- `https://docs.nats.io/nats-concepts/jetstream/consumers` redirected to `https://docs.nats.io/learn/jetstream/pull-consumers`. The final card uses the actual delivery/acknowledgment pages reached through current navigation. CLI fetch/flag examples were not generalized or executed.
- DuckDB's stable internals URL redirected through an interstitial to the2.0 documentation. PostgreSQL's `current` tutorial resolved to18. These labels do not establish compatibility with development HEAD; the cards explicitly separate their version boundaries.
- Long tool responses were narrowed to relevant source/comments/contracts, with stored response excerpts printed for actual inspection. Downloading a long file did not count as reading every branch. Source bodies and upstream images were not saved into the skill.

The sample is strongest on open-source, source-inspectable databases, runtimes and distributed infrastructure. It does not compare full application architectures, business domains, org structures, actual deployment configurations, implementation conformance or operational outcomes. A source-case mechanism can inform a question without justifying adoption of the whole product.
