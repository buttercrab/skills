# Design skills and tools: curation record

Inspection date: 2026-11-07. This lane contributes **27 original cards: 16 skills and 11 tools**. All are source inspections, not installation trials, output-quality experiments, screenshot critiques or endorsements. The cards are authoritative for exact URLs, revisions, scope and access labels.

## Discovery and inspection method

Started from the existing `fundamentals-deep` visual-design and skill-evaluation evidence, the user's ui.sh/Taster pointers, public skill collections, and searches for design workflows and implementation/verification tools. Directory and registry results were treated as discovery leads. Curated skills were followed into their primary instruction files; selected references, licenses and public tool documentation were then inspected to establish operational scope and dependencies. Mutable GitHub branches were resolved to commit IDs where practical. Existing rubric evidence is explicitly marked when retained instead of freshly fetched.

The first calibration pair was Anthropic frontend-design and axe-core: one generative direction source and one bounded verification tool. Parent review accepted the specific transfer/mismatch treatment and source-only evidence. Subsequent selection expanded beyond CSS taste into accessibility repair, motion performance, design-system extraction, questioning and exploration, native layout/state, prototyping, diagramming and review.

The investigation used read-only web and GitHub source retrieval plus local source reads for user-specified installed resources. It did not run remote scripts, install skills, change global configuration, invoke a design connector, execute a browser audit, open private member galleries or send external messages. No visual, documented-flow or interaction-tested evidence modes were inferred from prose descriptions.

## What the collection covers

Skill families include:

- **Visual direction and production:** Anthropic frontend-design, Impeccable, tasteskill, UI UX Pro Max, public Taster, installed ui.sh design.
- **Scoped implementation/review:** Vercel Web Interface Guidelines, Vercel React performance, shadcn project guidance, ibelick baseline-ui, fixing-accessibility and fixing-motion-performance.
- **Discovery and explicit decisions:** Superpowers brainstorming and ibelick create-design-md. These provide question/decision and extraction mechanisms, with their own workflow constraints rather than universal authority.
- **Native behavior:** SwiftUI expert and Android adaptive Compose, selected for layout, input and state continuity rather than visual novelty.

Tool families include axe-core and Lighthouse for bounded automated evidence; Playwright for stateful browser checks and screenshot comparisons; Storybook for component states and interaction checks; Chrome DevTools for rendered CSS diagnosis; Figma MCP for design-context retrieval and separately permissioned writes; Penpot for prototype connections; Excalidraw for system/flow sketching; Mobbin for access-dependent reference discovery; awesome-design-md for interpreted design documents; and the installed ui.sh comparison picker.

No score claims, star counts, download counts or repository popularity were used as evidence of effectiveness. Overlapping skill prescriptions are intentionally visible: mandatory typography, palettes, animations, stacks and layout recipes are house styles that can conflict with the user's brief or each other.

## Important source-specific findings

Impeccable's current canonical template is `skill/SKILL.src.md`; an older frontend-design path failed. The catalog follows the inspected current source rather than assuming an old local or registry package matches it. Taster's exact locally inspected commit was also accessible publicly, allowing a public pinned card; that does not make every local installation current.

ui.sh design and ideas were readable locally, but this pass did not establish their public distribution or license. Their two cards use optional `local:` identifiers and `local-only` availability. No personal home-directory path is a required catalog dependency. The picker card describes workflow dependencies and local-server/browser effects without invoking them.

The Android adaptive source explicitly requires Compose and Navigation 3, includes experimental APIs, and contains conflicting screenshot-baseline directions. The card surfaces this conflict rather than quietly treating either instruction as governing the user. SwiftUI material includes emerging SDK/platform claims; implementation must independently check compatibility against the actual project target.

Figma documentation separates retrieval and write capabilities. Hosted Excalidraw and the embeddable package do not have identical collaboration capabilities. Storybook component evidence does not establish whole-product journey quality. axe/Lighthouse automation does not establish accessibility acceptance. Screenshot equality does not establish usability or creative quality.

## Access failures, exclusions and remaining candidates

- Old Impeccable entrypoint, an assumed Android `skills/` directory, an obsolete Penpot docs route and a Chrome CSS overview route were unavailable at those addresses. Inspected canonical repository/docs routes replaced them; an unavailable URL was never counted as an inspected source.
- Mobbin inspection covered public marketing/search-entry material only. No paid/member screen set, versioned product flow or screenshot was inspected. Its `partial` card routes later authorized discovery; it does not recommend unseen examples.
- Awesome lists and skill registries are discovery infrastructure. Unread directory entries were not turned into substantive cards. The awesome-design-md card follows a directory and an actual interpreted design document, and labels the latter as an interpretation rather than product-owner documentation.
- Full skill-creator authoring/evaluation systems are relevant to maintaining the overall repository, but were not added to this design-selection lane merely to increase the count.
- Other installed ui.sh utilities, private/internal skills and generic AI tool directories remain candidates; local availability alone did not justify duplicate cards. No claim is made to have exhausted the internet or all design skills.

## Rights, updates and evidence limits

Cards are original annotations with links, not mirrored packages. License observations are narrow: selected MIT/Apache root or per-skill declarations were inspected, not every referenced asset or dependency. Source availability does not grant rights to bundled photographs, logos, icon sets, member screenshots or hosted-service output. Unknown rights remain explicit rather than inferred from a neighboring repository license.

For updates, check the owning primary file and its dependency references, not only a registry description. Compare changed rules, API versions, side effects and approval gates; retain previous inspection context when reclassification matters. Public marketing pages and member-service availability should be refreshed before use. Actual skill activation must still respect the user's objective, repository constraints, tool permissions and selected creative direction.

This was a broad primary-source curation pass with detailed entrypoint reading and selective reference/license inspection. It was not 27 independent executions or empirical validation. The next useful depth is task-specific: select plausible candidates with the human, inspect their nearest examples and full dependencies, and test the resulting interface against real journeys. Remaining gaps include observed native interaction evidence, real research/interview tooling, member-only references, complex enterprise workflows, localization/RTL and comparative outcome studies.
