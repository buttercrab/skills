# Systems and patterns curation receipt

Inspection date: **2026-11-07**. Owner: `curate_systems`. Scope: first-party design systems and decision patterns, not popularity ranking or a complete survey of their component libraries. These annotations are original selection guidance; no third-party packages, screenshots, fonts or brand assets are redistributed.

## Result and evidence boundaries

24 resource cards: **23 curated, one candidate**. All 24 have source-inspection receipts; nine include documented sequences, four have actual visual observations, and one includes a narrowly exercised interaction. These are overlapping modes, not independent studies. A system homepage, its pattern page and its example remain one maintainer family, not three corroborating authorities.

The task distinctions are deliberate: final correction versus multi-session orchestration; navigation destination versus tab panel; command menu versus input selection; empty data versus failed retrieval; a complete translated service versus a collection of translated materials; ready-made system versus unstyled behavior primitive. Cards ask for these discriminating facts and identify what the agent must inspect before borrowing. They do not assume a universal visual style or that a named system is automatically appropriate.

## Actual screen and interaction receipts

All visual inspection used an owned native Chrome tab at the public HTTPS URLs below through the documented CUA API. No localhost, local files, headless browser, account access or external write was used. No policy denial occurred. Source screenshots were viewed in tool output; they were not copied into this repository.

1. **GOV.UK check answers:** viewed embedded review example with blue GOV.UK header and grouped Personal details/Application details label-value-change rows separated by horizontal rules. No Change link or submit action exercised. Documented correction route remains distinct from this static visual observation.
2. **Material navigation bar:** viewed static news-app phone illustration with labeled News/Global/For you/Trending destinations and pill selected indicator around the For you star. No navigation switching, back-stack or saved-state interaction tested. Read actual source text about Expressive changes and platform availability.
3. **Apple onboarding:** read actual guidance and navigation through native Chrome; the viewed illustration was a waving hand and heading, not a native app screen. Accordingly the Apple cards make no app-screen visual-character claim and do not use visual evidence mode.
4. **Carbon data table:** viewed sizing guidance and comparative header/cell height diagrams. One initial click encountered a detached node; refreshed accessibility tree and used the fresh node successfully. This was a stale-element event, not a policy refusal. No table sorting, row expansion or batch mutation was exercised.
5. **Radix dialog:** clicked public Edit profile demo, observed open panel and focused Name field with existing Pedro Duarte data, then pressed Escape. Dialog disappeared and Edit profile trigger regained focus. Viewed the title, description, labels, close and Save controls with dimmed background. **Did not edit values or activate Save.** This is one open-dismiss cycle, not proof of persistence, complete keyboard containment or screen-reader conformance.

CUA work ended with its required completion summary immediately after observing the final Radix outcome.

## Coverage and unresolved gaps

- Government, enterprise/productivity, developer tools, commerce, native/mobile, creative-product ecosystems and one consumer-system candidate are represented. This lane is primarily system and behavior guidance; other lanes supply actual product flows and visual expression. Brand atmosphere must not be inferred from these names or source text.
- Only four cards carry actual screen receipts. Source-only cards keep empty character facets. Nine flow cards distinguish documented sequence from actual execution; only the Radix dialog card claims interaction-tested.
- No complete application, responsive matrix, screen-reader audit, performance benchmark, native runtime or installed library was tested. Documentation accessibility claims remain claims until the composed product is verified.
- Public availability does not settle copying rights. All cards use original notes and links, with observed GOV.UK licensing scoped to its own footer; other asset/code/font rights remain unverified.
- For maintenance, revisit mutable routes and statuses first: Polaris surface/version, Material Expressive/platform availability, Spectrum route/readiness, Gestalt content access, and component preview/stable labels. Preserve historical receipts when refreshing rather than changing dates without reinspection.
